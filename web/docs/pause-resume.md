# 会话暂停与继续

## 交互

- 执行中显示暂停 SVG。点击立即发出取消信号并返回“已暂停”，不等待模型、命令或工具结束。
- 空输入且可恢复时显示继续 SVG。点击基于已保存上下文启动新一轮，不重放上一轮原始请求。
- 可恢复时输入内容不会自动执行；主按钮变为发送。发送新消息时携带中断提示，新消息优先于旧目标。删除草稿后恢复继续按钮。
- 执行中有草稿/排队消息时，保留发送动作，并额外显示暂停按钮。
- 上一轮尚在释放会话执行锁时，可以立即接收一次续接请求，显示“已接收，等待旧请求取消”。禁止重复提交和同一 QueryEngine 并行执行。

## 计时显示

- 暂停时在原计时器左侧显示“已暂停”，保留同一行的时钟及累计用时；不足一秒显示 0s。
- 暂停与中断期间冻结计时，继续后累计实际执行时间，不归零，也不计入暂停及等待续接的时间。
- 正常完成后再发起的新任务重新计时；单轮请求和工具的独立耗时记录不变。
- 累计用时随执行状态持久化；进程被强制终止时，只能恢复最后已保存的累计值。

## 可继续的判断标准

由服务端持久化的 execution 状态决定，不分析回答中是否出现“完成”等词语：

| 状态 | 继续入口 |
| --- | --- |
| 用户暂停 | 有；下一轮注明用户主动打断 |
| 模型/网络/超时错误、工具或上下文异常、轮数上限 | 有；下一轮注明意外终止及原因分类 |
| 服务进程异常退出，记录仍为 running | 重开会话后转换为 interrupted，可继续 |
| 正常 completed，或正常让出给排队消息 turn_yielded | 无 |
| 新会话、仅浏览器 SSE 断连但后台仍运行 | 不推断为中断；以重新同步的服务端状态为准 |

认证、模型配置、图片输入或上下文限制类错误也保留恢复入口，但应先修复原因；可恢复不保证下一次请求一定成功。不会自动无限重试。

## 续接提示与实际停止边界

下一轮通过请求上下文注入用户打断/异常终止说明，要求核实文件、命令、进程及外部操作的实际状态，不能把“没有结果”当成“没有执行”，不能无条件重复副作用操作。补充指令按新约束执行；替换/取消指令覆盖旧目标；独立问题优先回答；有副作用且意图不明时先澄清。

模型流取消不等待 provider 的 next()/return()，迟到的流输出不会进入已结束轮次。工具等待可中断。由当前 terminal_run 启动且仍处于前台等待的命令收到终止信号；独立后台命令及子任务不被无差别杀死。远端请求、第三方工具或已经完成的写入无法保证瞬间撤销，恢复时必须核实。

暂停/异常状态独立记录在 transcript.jsonl 中，不被上下文压缩删除。旧版历史如果没有执行状态记录，不凭最后一句回答猜测是否应继续。

## 压缩中暂停

- 手动、排队、自动和上下文超限触发的压缩均支持取消；立即停止等待，不等摘要模型返回。
- 摘要完整生成且提交前，上下文保持压缩前状态。暂停后的迟到结果不提交，也不生成降级摘要来替换原上下文。
- 待重新压缩标记随执行状态落盘。继续或进程重启恢复后，先基于保留的上下文重新生成压缩检查点，再调用普通模型；不补造“继续”用户消息。
- 若用户发送新内容，仍以新消息为准，重新压缩时一并保留。已成功提交的检查点不回退，工具及外部写入不重放或撤销。
